## 1. Security findings

### Critical
1. **Plaintext KRA PIN in pre-payment response** — `app/api/kra/retrieve/route.ts` (~L797–805) returns `pin: fullPin` in the `captchaRequired` (422) response for ID-based lookups. An anonymous caller can enumerate full PINs without paying, defeating the sealed-blob design. **Fix: return masked data only.**

### High
2. **Evolution API key committed to repo & history** — `akubrecah_secret_whatsapp_key_2026` appears in `.env.example`, both `docker-compose.yml` files, and `deploy/update_app.sh`. It gates `/api/generate-certificate` and WhatsApp webhook auth. **Rotate now; purge from git history (`git filter-repo`); make it env-only everywhere.**
3. **Payment entitlement hijack via phone matching** — WhatsApp `paid <phone>` / `/recheck <phone>` matches any successful Paystack transaction by last-9-digits of phone within a 90–180 min window (`app/api/whatsapp/chat/route.ts`, `lib/paystack.ts` `findRecentSuccessfulPaystackPayment`). Anyone who knows a payer's phone can get the victim's certificate delivered to their own chat. **Bind payments to the requesting conversation/session ID.**
4. **PII & secrets in stdout logs** — full session cookies, full PINs (retrieve, `charge-mpesa`, `nil-return`, `certificate-fulfillment`). The pino redact list never matches because args are wrapped as `{data: ...}` in the console adapter. **Fix the redact paths; scrub call sites.**
5. **Unencrypted PII at rest** — full PINs and taxpayer PII in `CertificateDownload.pin`, `ai_conversations.metadata`, `sessions.pin`, `Inquiry`, and the unused-but-live `kra_pin_cache` table. Contradicts the zero-storage/KDPA posture. **Encrypt or drop; add retention/TTL on `SystemLog`.**

### Medium
6. Non-timing-safe master PIN comparison in `app/api/admin/magic-login/route.ts`.
7. Any WhatsApp sender with `ADMIN_BOT_PIN` in text can `/link` and get a Super Admin magic-login URL.
8. Webhook secrets accepted via query params (`?secret=`, `?token=`) — leaks into proxy logs.
9. Non-constant-time secret check on `/api/whatsapp/chat`.
10. Download tokens not bound to paying session — `checkoutId` (non-secret) can mint a `downloadId` entitlement.
11. Paystack `/verify` subscription path: no amount floor; returns plaintext PIN to anyone holding the reference.
12. Unauthenticated payment-status oracle at `/api/mpesa/status/[checkoutRequestId]`.
13. Taxpayer `pin`+`password` held in plaintext in `globalThis.kraSessions`; dead macOS Chrome path; `--no-sandbox` Playwright.
14. Unauthenticated `/api/analytics/track` upserts arbitrary rows (DB pollution); doesn't use the existing telemetry sanitizer.
15. Client-supplied base64 cookies forwarded verbatim to `itax.kra.go.ke`.
16. Container: Dockerfile runs as root, bakes Clerk keys, non-reproducible installs (`--legacy-peer-deps || npm install`); compose publishes port 3005 bypassing Caddy, passwordless Redis, hardcoded Evolution DB password, public Evolution on :8085, `tls_insecure_skip_verify` in Caddyfile.

### Low
- Secrets (serviceSecret, Evolution master key, full PIN) POSTed to n8n on every fulfillment.
- `Math.random()` payment references (non-crypto).
- Hardcoded bot-owner phone duplicated in 4 files.
- Weak CSP in report-only mode; `X-Frame-Options` conflict (DENY vs SAMEORIGIN); loose host matching via `includes('kra')`.
- `maskTaxpayerData` spreads unknown keys through unmasked.

### What's done well
- Sealed-PIN transport (`kraseal1:` AES-256-GCM) with dedicated tests — genuinely good KDPA-aligned design.
- Paystack webhook HMAC over raw body, timing-safe; M-Pesa callback token fails closed.
- Idempotent entitlements, underpayment rejection, PIN-metadata binding (kills cross-PIN unlock).
- Layered rate limiting with fail-closed IP provenance; middleware security headers, scanner blocking, open-redirect/path-traversal guards.
- Zero-storage discipline on the live-lookup path (no-op caches, log sanitizer).

## 3. Code quality

- **Duplication:** KRA proxy/session/HTTP helpers copy-pasted across 3 files (`retrieve`, `captcha`, `lib/kra-api.ts`); admin identity checks re-implemented inline instead of `verifyAdminCaller`. Fixes will silently miss copies.
- **`prisma as any`** across nearly all sensitive routes — no type safety on the most critical DB surface.
- **Dead code:** no-op caches, unused proxy matcher, stray subscription paths with drifting amounts (300/499/500), `.jsx` stragglers, committed `.agent/` state, `tsconfig.tsbuildinfo`, duplicate logo files, unrelated `.docx`/`.pdf` in `public/`.
- **Error handling:** empty `catch {}` silently downgrading auth; `error.message` returned to clients; all handler errors mapped to HTTP 400.
- **Tests:** 14 solid utility suites (masking, rate-limit, telemetry, flags) but **zero route-handler or payment-flow tests** — exactly where findings 1, 3, 10, 11 live.
- **tsconfig:** `strict: true` on (good); add `noUncheckedIndexedAccess`; clean stale `include` entries.
