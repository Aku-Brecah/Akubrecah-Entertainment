## 3. Payment Integrity

| # | Severity | Finding | Status |
|---|----------|---------|--------|
| 3.1 | 🔴 CRITICAL | **One payment minted certificates for any PIN.** `record-download` validated M-Pesa payment success but never compared the paid PIN to the requested PIN. Chain: pay KES 20 for PIN A → `record-download {checkoutId, pin: B}` → certificate for B. | ✅ **FIXED** — PIN is bound at STK dispatch time (`lib/whatsapp/mpesa-dispatch.ts`), merged into payment proof at callback, and enforced in `record-download` (403 on mismatch, including the `alreadyRecorded` reuse path). |

| 3.4 | 🟠 MEDIUM | `Subscription` had no DB-level dedupe → concurrent webhook+verify could mint two 30-day subscriptions. | ✅ **FIXED** — `@@unique([mpesaReceipt])` on `subscriptions` + P2002 handled idempotently in webhook and verify. **Run `npx prisma migrate dev` (or `db push`) on the production DB.** |

| 3.8 | ✅ OK | Server-side pricing everywhere on the real flows (`PAYSTACK_DOWNLOAD_FEE_KES`, fixed KES 20 constants; no amount accepted from clients); admin rejection on all payment endpoints; Paystack webhook HMAC is timing-safe with raw-body verification; Daraja callback token timing-safe and fail-closed. | Verified |

## 7. Code Quality / Architecture (documented)

- `app/api/kra/retrieve/route.ts` is a ~900-line route — extract the KRA gateway logic into `lib/`.
- No `$transaction` usage in fulfillment mint paths; unique-constraint backstops added where it matters most (3.4).
- `stkpush/route.ts` re-exports helpers from an App Router file — move to `lib/`.
- Root-level draft `.md` files (`API_MIGRATION_SUMMARY`, `IMPLEMENTATION_*`, `UPDATED_IMPLEMENTATION`, `SEO_AUDIT_AND_GUIDE`, `STAGING`, per-feature notes) — archive into `docs/archive/`.
- `scratch/` contains KRA captcha screenshots and page dumps committed to git history — sensitive capture liability; purge from history when convenient.
- `public/c95843a0d5c040d6832dbff09ce6a213.txt`, `public/google41e64c96aba6d4b0.html` are verification probes — fine to keep.
- Residual hardening ideas: `settings` POST key allowlist + audit log; rate-limit tier for `charge-mpesa`/`verify`; webhook flood protection; dedicated service tokens instead of `EVOLUTION_WEBHOOK_SECRET` for admin API service calls.
